## What (v1.6 #1 + #3 — ADR-037)
Completes ADR-023's OOM classification. The worker JVM runs `-XX:MaxRAMPercentage=75` + `-XX:+ExitOnOutOfMemoryError`, so a **heap** OOM is hit *below* the cgroup wall and the JVM self-exits via HotSpot `os::exit(3)` → container `ExitCode=3, OOMKilled=false`. `exit_diagnosis()` only matched `OOMKilled`/`137` (the cgroup native-overrun path), so this **common** large-binary OOM (v1.5 #5 spike: `light@4GiB` on a 192 MB binary) was mis-classified as a **retryable** `worker-unavailable` instead of the non-retryable `resource-exhausted`.
